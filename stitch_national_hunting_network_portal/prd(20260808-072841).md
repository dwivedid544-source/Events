# Product Requirements Document (PRD)

## Nationwide Hunting Club, Membership & Event Management Platform

---

# 1. Product Overview

This product is a nationwide digital platform for managing hunting clubs, state associations, events, memberships, participants, dogs, results, merchandise, revenue, sponsors, and administration.

The platform follows a hierarchical organization structure:

```text
National Organization
        ↓
State Association
        ↓
Local Club
        ↓
Member
```

Events and shared information should flow upward through the organization:

```text
Club Event
   ↓
Club Page
   ↓
State Page
   ↓
National Event Calendar
   ↓
Event Search
   ↓
Map / Discovery
```

The platform must operate as one connected ecosystem rather than separate disconnected websites.

A member should use one account across the entire network.

The product includes:

- Public National Website
- State Association Public Pages
- Local Club Public Pages
- Find Hunt / Event Discovery
- Membership Joining & Checkout
- Member Portal
- Club Admin Portal
- State Admin Portal
- Event Admin Portal
- National Admin Portal
- Super Admin Portal

---

# 2. Product Goal

The main goal is to create a centralized digital ecosystem where members, clubs, state associations, event managers, national administrators, and platform administrators can manage their activities from one system.

Users should be able to:

- Find hunting events
- Find nearby clubs
- Explore state associations
- Join clubs
- Purchase memberships
- Enter events
- Manage dogs
- View results
- Purchase merchandise
- Read news
- View sponsors
- Manage local clubs
- Manage state-level operations
- Manage events
- Manage national operations
- Manage platform-wide administration

The platform should reduce duplicate work.

For example, when a Club Admin creates an event once, that event should be able to appear automatically in:

- Club Page
- State Event Listing
- National Event Listing
- Find Hunt Search
- Calendar View
- Map View

---

# 3. Current UI Phase Scope

The current project phase focuses on FRONTEND UI/UX.

The UI should include:

- Navigation
- Dashboards
- Sidebars
- Headers
- Cards
- Tables
- Forms
- Search
- Filters
- Calendar layouts
- Map placeholders
- Modals
- Status badges
- Empty states
- Responsive layouts
- Role-specific screens

Real backend functionality is not required during this UI generation phase.

Do not implement:

- Backend APIs
- Database logic
- Real authentication
- Payment processing
- JWT
- OAuth
- Real permissions logic
- Server-side data processing

Realistic dummy data should be used for UI design.

# 7. Permission & Scope Model

The UI must clearly reflect each user's assigned scope.

## Member Scope

```text
Own Account Only
```

The member sees:

- Own profile
- Own dogs
- Own memberships
- Own orders
- Own entries

---

## Club Admin Scope

```text
Assigned Club Only
```

Example:

```text
Oak Ridge Hunting Club
Knoxville, Tennessee
```

The Club Admin must not see another club's private management data.

---

## State Admin Scope

```text
Assigned State Only
```

Example:

```text
Tennessee
```

The State Admin can manage clubs and events inside Tennessee only.

---

## Event Admin Scope

```text
Assigned Event Only
```

Example:

```text
Nite Hunt
September 19, 2026
Oak Ridge Hunting Club
```

---

## National Admin Scope

```text
National Organization
```

National Admin can access national-level operational data.

---

## Super Admin Scope

```text
Entire Platform
```

Super Admin has full platform-level administrative visibility.

- Typography

- Header
- Cards

- Buttons
